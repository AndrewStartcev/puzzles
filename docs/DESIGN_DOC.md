# Мир пазлов — Design Document

**Статус:** рабочий дизайн-документ  
**Платформа:** Vite + React + TypeScript + PixiJS/WebGL; Пикабу Игры, VK Mini Apps/игры, Одноклассники
**Основной сценарий:** desktop/web, адаптация под мобильные экраны  
**Версия документа:** 0.2

Документ описывает целевой продукт, включая будущие возможности. Реализованный scope ядра и UI перечислен в README. Архитектура и ограничения — в TECH_DECISION_WEB.md. Старый Godot-прототип удалён; его история доступна в Git. Яндекс Игры не поддерживаются.

---

## 1. Видение продукта

Наша игра — не просто один экран с пазлом, а полноценный **долгоиграющий puzzle-hub**: игрок выбирает изображения, собирает их на разных уровнях сложности, открывает коллекции, возвращается за ежедневным пазлом, получает награды и постепенно персонализирует игровое пространство.

Ключевая особенность производства контента: **одно исходное изображение автоматически превращается в пазлы любой поддерживаемой сложности**, без ручной нарезки ассетов.

Главные цели:

- очень быстрый вход в игру;
- приятное ощущение настоящего физического пазла;
- десятки и сотни изображений без ручной подготовки деталей;
- режимы от короткой сессии на несколько минут до больших пазлов на несколько часов;
- понятная долгосрочная прогрессия;
- монетизация без разрушения базового игрового процесса;
- визуальный стиль заметно светлее, чище и современнее прямого конкурента.

---

## 2. Что берём из конкурентного продукта

По предоставленным референсам конкурент хорошо решает **структуру продукта**, но визуально слишком сильно уходит в коричнево-оранжевую гамму. Мы используем его только как функциональный референс, без копирования интерфейса.

### Что стоит взять как продуктовые идеи

- большая библиотека пазлов;
- коллекции по темам;
- быстрый старт;
- «Продолжить» последний пазл;
- случайный пазл;
- пазл дня;
- выбор количества деталей перед стартом;
- несколько классов сложности;
- длительные пазлы на сотни и тысячи деталей;
- ежедневные награды;
- календарь активности;
- задания;
- звёзды / достижения;
- внутренняя валюта;
- магазин;
- косметические столы;
- фоны;
- рамки;
- музыка;
- подсказки;
- автосборка как расходуемый бонус;
- возможность убрать рекламу;
- открытие тематических коллекций;
- прогресс по конкретному изображению;
- сохранение незавершённого пазла;
- игровая область с отдельным лотком деталей.

### Что у конкурента не берём

- тотальную коричнево-оранжевую палитру;
- тяжёлые золотые рамки почти вокруг каждого элемента;
- перегруженность экрана одинаковыми акцентами;
- визуальное ощущение магазина/казино вместо спокойной puzzle-игры;
- чрезмерно тёмные карточки изображений;
- постоянный оранжевый цвет как единственный CTA-акцент.

## 3. Визуальное направление

### 3.1. Общее настроение

Игра должна ощущаться как **спокойный современный премиальный puzzle-table**, а не как мобильная F2P-игра 2018 года.

Ассоциации:

- дерево;
- бумага;
- матовый пластик;
- мягкая ткань;
- естественный дневной свет;
- спокойные природные оттенки;
- чистые карточки;
- фотография или качественная иллюстрация всегда важнее UI-декора.

### 3.2. Базовая палитра

Основная тема — нейтральная тёплая.

- фон приложения: графитово-коричневый / серо-бежевый;
- рабочий стол: натуральные деревянные и текстильные варианты;
- панели: нейтральные полупрозрачные тёмные или светлые;
- основной акцент: мягкий янтарный / золотой, но только точечно;
- вторичный акцент: шалфейный зелёный или холодный сине-серый;
- успешное действие: зелёный;
- сложные режимы: красный/фиолетовый только в маркировке сложности.

Правило: **оранжевый не должен занимать больше 5–10% интерфейса одного экрана**.

### 3.3. Детали пазла

Важнейший визуальный объект игры.

Требования:

- без серой технической обводки;
- картинка должна быть самой поверхностью детали;
- мягкая естественная тень;
- при поднятии тень усиливается;
- установленная деталь практически сливается с изображением;
- геометрия выступов должна напоминать фабричный пазл;
- соседние контуры должны совпадать абсолютно точно;
- размер выступов умеренный;
- допускается небольшая вариативность формы между соединениями;
- внешний край собранного пазла идеально ровный.

# 5. Главный экран

Главный экран должен решать одну задачу: **дать начать играть за 1–2 клика**.

## Основные блоки

### Продолжить

Если есть незавершённый пазл:

- превью;
- название;
- количество деталей;
- прогресс `124 / 300`;
- процент;
- кнопка «Продолжить».

### Быстрый старт

Три крупных карточки:

- **Случайный пазл**;
- **Пазл дня**;
- **Выбрать из коллекции**.

### Рекомендуемые коллекции

Горизонтальная лента карточек.

### Недавно открытые / избранное

Вторичный блок ниже первого экрана.

### Статус игрока

Компактно в шапке:

- монеты;
- звёзды;
- серия дней;
- профиль;
- настройки.

Не превращать шапку в панель из 8 валют.

# 6. Библиотека и коллекции

Изображения группируются в тематические коллекции.

Примеры стартовых коллекций:

- Природа;
- Животные;
- Города мира;
- Уютные места;
- Космос;
- Фэнтези;
- Машины;
- Архитектура;
- Еда;
- Море;
- Горы;
- Сказочные иллюстрации.

## Карточка пазла

Карточка показывает:

- большое изображение;
- название;
- статус: новый / начат / собран;
- лучший результат;
- количество полученных звёзд;
- избранное;
- при необходимости значок premium/locked.

Изображение должно занимать большую часть карточки. UI не должен затемнять его без необходимости.

## Открытие коллекций

Варианты:

- бесплатные стартовые коллекции;
- за игровую валюту;
- за достижения;
- за серию дней;
- premium-наборы;
- сезонные бесплатные наборы.

Основной контент нельзя прятать только за оплатой.

# 7. Выбор сложности

Перед стартом игрок видит крупное превью картинки и набор уровней.

## Предлагаемые классы

### Лёгкий

- 12;
- 16;
- 24;
- 36.

### Средний

- 48;
- 64;
- 100;
- 144.

### Сложный

- 225;
- 300;
- 400.

### Мастер

- 625;
- 768;
- 1024.

### Эксперт

- 1200;
- ~2000;
- до ~3000.

Фактическое количество может немного отличаться, поскольку сетка должна соответствовать пропорциям исходного изображения и сохранять близкую к квадратной форму базовой ячейки.

Например для 4:3 целевого режима 3000 допустимо `63 × 47 = 2961`.

## Для каждой сложности показывать

- реальное количество деталей;
- примерное время;
- награду;
- лучший результат пользователя;
- статус прохождения;
- рекомендованный режим.

# 8. Игровой экран

Это главный UX игры.

## 8.1. Компоновка desktop

### Центр

Большой рабочий стол и область сборки.

### Справа

**Один вертикальный лоток деталей**.

Идея конкурента удачная: несобранные детали идут в одну линию и прокручиваются.

Преимущества:

- игрок не ищет кусочки в хаотичной куче;
- изображение в центре остаётся чистым;
- легко поддерживать большие наборы;
- понятный скролл;
- можно виртуализировать список для 1000–3000 элементов.

Для больших пазлов рендерить только видимую часть лотка + небольшой buffer.

### Слева

Узкая панель инструментов:

- показать образец;
- сменить стол;
- собрать все детали обратно в лоток;
- рамка/режим края;
- подсказка;
- авто-действие при наличии бонуса.

### Сверху

- назад;
- название;
- таймер;
- прогресс `54 / 300`;
- пауза;
- при необходимости zoom indicator.

---

## 8.2. Масштаб и большое игровое поле

Для 12–100 деталей поле может почти помещаться в экран.

Для 300–3000 деталей рабочая поверхность становится физически намного больше viewport.

Обязательные функции:

- zoom колесом;
- pan средней/правой кнопкой мыши;
- drag пустого пространства при подходящем режиме;
- `F` — показать весь пазл;
- кнопки `+ / −`;
- reset zoom;
- ограничение минимального и максимального масштаба;
- zoom относительно позиции курсора;
- сохранение положения камеры между сессиями.

Главное правило: **деталь не должна становиться микроскопической только потому, что выбран режим 3000**.

---

## 8.3. Лоток деталей

Desktop:

- справа;
- одна колонка;
- вертикальный scroll;
- крупные детали;
- drag прямо из лотка на стол.

После правильной установки деталь исчезает из лотка.

Дополнительные режимы сортировки позже:

- все;
- только крайние;
- по цвету;
- по зоне изображения;
- случайный порядок.

Для мобильного устройства лоток превращается в нижнюю горизонтальную ленту.

# 9. Подсказки

Подсказки не должны автоматически решать игру слишком часто.

Виды:

### Показать образец

На 2–5 секунд показывает исходную картинку поверх поля или отдельным preview.

### Найти место

Выбранная деталь мягко подсвечивает приблизительный сектор.

### Поставить деталь

Автоматически устанавливает одну деталь.

### Крайние детали

Фильтрует tray, оставляя только край.

Подсказки можно получать:

- за игру;
- ежедневно;
- за rewarded-рекламу;
- за валюту;
- из premium-наборов.

---

# 10. Пазл дня

Один общий пазл на день.

Особенности:

- одинаковое изображение для всех игроков;
- фиксированный основной уровень сложности;
- можно разрешить выбрать облегчённый вариант;
- отдельная награда;
- серия дней;
- календарь прохождений;
- бонус за 7 дней подряд.

Награды не должны заставлять входить строго каждый день под угрозой потери всего прогресса. Серия может иметь 1 «страховочный» день.

---

# 11. Ежедневные награды

7-дневный цикл.

Пример:

- День 1 — монеты;
- День 2 — монеты;
- День 3 — подсказка;
- День 4 — монеты;
- День 5 — авто-деталь;
- День 6 — монеты + подсказка;
- День 7 — крупный сундук / ключ / косметика.

Экран должен быть светлее и проще конкурентного референса.

Не делать 10 типов наград одновременно.

---

# 12. Задания

## Ежедневные

Примеры:

- собрать 1 пазл;
- поставить 30 деталей;
- собрать пазл не сложнее 100 деталей;
- использовать образец 1 раз;
- собрать 10 крайних деталей.

## Долгосрочные

- собрать 10 пазлов природы;
- поставить 1000 деталей;
- собрать пазл на 300+ деталей;
- завершить 7 пазлов дня;
- пройти коллекцию.

---

# 13. Прогресс и звёзды

У каждой картинки может быть до 5 звёзд.

Звёзды выдаются не за скорость, а прежде всего за уровни сложности, чтобы игра оставалась расслабляющей.

Пример:

- первая сборка — 1 звезда;
- 100+ деталей — ещё 1;
- 300+ — ещё 1;
- 600+ — ещё 1;
- 1000+ — ещё 1.

Так игрок может возвращаться к любимой картинке.

---

# 14. Экономика

## Основная валюта — монеты

Получение:

- завершение пазлов;
- ежедневные награды;
- пазл дня;
- задания;
- достижения;
- rewarded-реклама.

Траты:

- новые коллекции;
- столы;
- фоны;
- рамки;
- музыкальные треки;
- отдельные косметические эффекты.

## Не плодить валюты

На старте достаточно:

1. монеты;
2. звёзды как прогресс/достижения;
3. подсказки как расходник.

Ключи и другие валюты добавлять только если появится реальная механическая необходимость.

# 15. Магазин

Магазин — сильная идея конкурента, но должен быть гораздо чище.

## 15.1. Косметика

### Столы

Меняют поверхность игрового поля:

- светлый дуб;
- тёмный орех;
- пробка;
- зелёный сукно;
- синее сукно;
- серый камень;
- тёплый мрамор;
- минималистичный матовый стол.

Стол не должен мешать читаемости деталей.

### Фоны

Меняют пространство за рабочим столом.

### Рамки

Меняют рамку зоны итогового изображения.

### Музыка

Паки фоновой музыки:

- piano;
- lo-fi;
- nature ambient;
- acoustic;
- fantasy;
- без музыки.

Музыку можно отдельно выключить в настройках.

---

## 15.2. Полезные покупки

Возможные постоянные покупки:

- убрать рекламу;
- открыть все базовые коллекции;
- cosmetic bundle.

Платные преимущества не должны ломать игровую механику.

---

# 16. Реклама

Реклама вторична по отношению к игре.

### Rewarded

Подходит для:

- +1 подсказка;
- поставить одну деталь;
- удвоить награду после пазла;
- получить дополнительные монеты.

### Interstitial

Допустимо:

- после завершения пазла;
- не после каждой короткой сессии;
- не посреди сборки;
- не при возврате из паузы.

После покупки «без рекламы» interstitial отключается, rewarded остаётся только как добровольный вариант бонуса.

---

# 17. Случайный пазл

Одна из центральных кнопок главного экрана.

Алгоритм:

- выбирает картинку из открытых коллекций;
- старается не повторять последние изображения;
- учитывает любимые категории;
- предлагает последнюю выбранную сложность;
- можно нажать «другой» до старта.

В дальнейшем возможен режим «Сюрприз»: изображение полностью открывается только после частичной сборки.

---

# 18. Сохранение

Для каждого активного пазла сохраняем:

- image_id;
- grid size;
- seed формы деталей;
- позиции всех неустановленных деталей;
- установленные детали;
- порядок tray;
- zoom;
- camera position;
- elapsed time;
- используемый стол;
- состояние подсказок.

Критически важно хранить **seed генерации**, а не сериализовать геометрию тысяч деталей.

Игрок должен иметь возможность закрыть пазл на 3000 деталей и вернуться через несколько дней ровно в то же состояние.

---

# 19. Работа с 1000–3000 деталями

Это отдельный технический режим.

Требования:

- не создавать тяжёлую физику на каждую деталь;
- ручной hit-test или spatial index;
- виртуализированный tray;
- culling невидимых деталей;
- LOD: на дальнем zoom не рисовать тени и мелкие эффекты;
- детали вне viewport не должны активно обновляться;
- одна исходная texture;
- seed-based geometry;
- минимизировать количество CanvasItem/Node при необходимости дальнейшей оптимизации.

Цель: режим 3000 должен быть реально играбельным, а не просто доступным в меню.

---

# 20. Контентная модель

Каждый пазл — запись с метаданными.

Пример:

```json
{
  "id": "nature_001",
  "title": "Домик у горного озера",
  "image": "assets/puzzles/nature/nature_001.webp",
  "collection": "nature",
  "tags": ["mountains", "lake", "forest"],
  "premium": false,
  "featured": true
}
```

Изображение само по себе не содержит сложности. Сетка генерируется при старте.

Это позволяет одной картинке поддерживать все режимы от 12 до ~3000 деталей.

# 21. Контент на релиз

Минимальная цель для ощущения полноценной игры:

- 6 коллекций;
- по 12–20 изображений;
- всего 80–120 пазлов;
- 8–10 столов;
- 6–8 фонов;
- 3–5 музыкальных тем;
- ежедневный пазл;
- случайный пазл;
- 20+ достижений;
- ежедневные задания.

Если производство изображений автоматизировано, лучше стартовать ближе к 150 изображениям.

# 23. Принципы, которые нельзя ломать

1. **Картинка — главный герой.** UI не должен конкурировать с ней.
2. **Пазл должен ощущаться физическим.** Никаких технических контуров вокруг деталей.
3. **Большая сложность не означает микроскопические детали.** Увеличивается рабочая поверхность.
4. **Игрок не обязан искать детали в хаотичной куче.** Основной источник деталей — прокручиваемый tray.
5. **Монетизация не мешает сборке.** Никакой рекламы посреди пазла.
6. **Одна картинка поддерживает все сложности.** Не создаём отдельные нарезанные ассеты.
7. **Сохранение обязательно.** Особенно для 300–3000 деталей.
8. **Минимум валют.** Экономика должна быть понятной.
9. **Акцентный цвет используется дозированно.** Не повторяем тотальную оранжевую гамму конкурента.
10. **Desktop-first, mobile-ready.** На мобильном меняется компоновка, но не логика игры.

# 24. Следующий дизайн-шаг

После стабилизации ядра нужно сделать единый визуальный концепт четырёх ключевых экранов:

1. Главная;
2. Библиотека/коллекции;
3. Выбор сложности;
4. Игровой экран.

Только после утверждения этих четырёх экранов имеет смысл рисовать магазин, календарь, задания и профиль.

Референсы конкурента используются для понимания функциональной плотности и состава экранов, **не как макет для копирования**.
