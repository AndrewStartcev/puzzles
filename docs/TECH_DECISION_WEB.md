# Мир пазлов — техническое решение

Обновлено 2026-09-13. Production: Vite SPA, React, strict TypeScript, PixiJS 8 с принудительным WebGL. Next.js / SSR не нужны. Godot был исследовательским прототипом и удалён из main; доступен только в истории Git.

## Слои

React отвечает за каталог, сложность, настройки и композицию игры. PuzzleSession отвечает за статусы и snap без зависимости от DOM, React или SDK. Генератор и earcut работают в Worker. Каждый shared edge генерируется один раз и используется соседями в обратном порядке: стыки совпадают точно.

PixiJS получает модель и callbacks. У всех деталей одна texture: UV рассчитываются по целевым координатам, мировые позиции управляют переносом отдельно. Технической обводки нет. SVG-превью tray использует тот же контур и исходное изображение; отдельных растров для тысяч деталей не создаём.

## Масштаб

12, 48, 108, 300, 768, 1200, ~2000, ~3000. Сетка оптимизирует количество и пропорции, предел 3000. Мировая ширина детали 160, высота зависит от сетки и картинки. Для больших пазлов начальный zoom не ниже 0.35; fit отдельно даёт полный обзор.

Данные — простые массивы. Renderer сканирует позиции при input/resize, создаёт только видимые meshes и освобождает ушедшие за viewport. Shared texture и mesh batching. Tray создаёт видимые строки плюс overscan. DPR ограничен 2. PixiJS и платформенные SDK разделены на ленивые chunks.

Это фундамент для 3000 деталей, а не обещание FPS на любом устройстве. Нужно измерить заполненный стол, memory, draw calls, frame times на реальных устройствах. При необходимости добавить spatial index, pool / LOD и объединённую геометрию. Сейчас culling и hit testing O(N), без тысяч event listeners.

## Сохранение

SaveGame содержит version=1, geometryVersion=1, contentId, seed, исходные размеры, сложность, позиции/статусы, камеру, elapsedSeconds и updatedAt. Геометрия восстанавливается по seed. Валидатор отвергает повреждённые / несовместимые данные, позиции поставленных деталей нормализует. При изменении размеров ассета нужен новый пазл; изменение генератора требует повышения geometryVersion и миграции.

Один активный пазл на платформу/устройство. Новый пазл заменяет сохранение, UI сообщает об этом. LocalStorage синхронно записывает checkpoint при закрытии и смене экрана: debounce 350 мс, период 10 секунд. Время учитывает только видимую вкладку и незавершённую игру. Ошибка хранилища показывается игроку.

Добавлены необязательные поля rotation (число четвертей оборота 0–3), rotatable, hintOpacity (0–1) и guideVisible. Старые v1-сохранения читаются без миграции: отсутствующий поворот равен нулю. Валидатор проверяет диапазоны и разрешает ненулевой поворот только свободным раскиданным деталям. Snap проверяет нулевую ориентацию; hit testing использует обратное преобразование вокруг центра детали.

PlatformAdapter: init, ready, async load/save, sync flush, capabilities. Следующий этап облака должен сохранить локальный checkpoint и добавить async очередь синхронизации, выбор свежего snapshot и привязку к профилю. Не хранить секреты / ключи подписи в VITE-переменных.

## Площадки

- LocalAdapter: хранение на устройстве без SDK.
- PikabuAdapter: динамический SDK, единственный init, ready → gameStarted.
- VkAdapter: официальный vk-bridge, VKWebAppInit.
- OkAdapter: официальный FAPI, init с api_server / apiconnection из launch parameters.

Для hosted adapters cloudSave / ads / payments сейчас false. Инициализация не означает полную сертификацию. Не подключать фиктивные rewarded callbacks или неподтверждённые методы. Проверять в зарегистрированных тестовых контейнерах. VK Games вне Mini Apps может потребовать отдельный launch flow внутри VK-адаптера.

Официальные точки входа: [PixiJS Mesh](https://pixijs.com/8.x/guides/components/scene-objects/mesh), [Пикабу SDK init](https://games.pikabu.ru/sdk/docs/sdk/init), [VK Bridge](https://github.com/VKCOM/vk-bridge), [OK FAPI init](https://apiok.ru/en/dev/sdk/js/init).

Яндекс Игры исключены. SDK и адаптер для них отсутствуют.

## Продуктовые этапы

Текущий scope — ядро и базовый UI. Коллекции 35+, daily, магазин, экономика, музыка и платежи — после визуального и performance review ядра; не смешивать их с renderer. Metadata вынесены в src/content; текущие карточки используют тестовые ассеты.
