# Мир пазлов — план следующей сессии

Дата фиксации: **2026-09-12**.

## Цель следующей сессии

Собрать первый production-web-прототип **«Мир пазлов»** на новом стеке и проверить, что PixiJS подходит для реального игрового поля лучше Godot Web.

## Порядок работ

1. Создать Vite + React + TypeScript приложение в текущем репозитории, не удаляя Godot-прототип.
2. Подключить PixiJS.
3. Перенести математическую модель генерации пазла из Godot в TypeScript.
4. Загрузить одну тестовую картинку из `assets/puzzles/`.
5. Сделать режим 12–16 деталей.
6. Реализовать:
   - процедурный контур;
   - UV/texture mapping;
   - drag;
   - snap;
   - правильную сборку соседних деталей.
7. Сделать рабочую камеру:
   - wheel zoom;
   - pan;
   - fit-to-board;
   - zoom относительно курсора.
8. После рабочего ядра добавить React-экран выбора сложности.
9. Проверить 100 / 300 деталей.
10. Отдельно провести performance-тест 1000+ деталей до начала полноценной UI-разработки.

## Что не делать в первой итерации

Пока не тратить время на:

- магазин;
- daily;
- задания;
- финальную экономику;
- Яндекс SDK;
- Пикабу SDK;
- платежи;
- большое количество контента.

Сначала нужно подтвердить production-ядро: **красивые детали + быстрый WebGL renderer + нормальный zoom/pan + сохранение структуры пазла**.

## Критерий успеха

Следующая сессия считается успешной, если одна картинка автоматически превращается в красивый пазл в браузере и:

- детали визуально похожи на реальные;
- текстура отображается без артефактов;
- drag/snap ощущаются нормально;
- поле свободно масштабируется;
- архитектура не требует отдельной ручной нарезки картинок;
- есть понятный путь к режимам 1000–3000 деталей.
